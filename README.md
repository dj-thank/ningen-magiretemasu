# ニンゲン、まぎれてます。

**AIの中に、友達がいる。**

友達の一文を、その場でLLMが作った四つの回答に混ぜて見抜く、日本語の3〜8人向けパーティーゲームです。主催者が部屋を作り、参加者はURLか6文字のルームコードで集まります。参加者のアカウント作成・APIキー入力・マイクは不要です。

このリポジトリは開発中の試作版です。ゲーム本体と生成APIの実装・ローカル検証はあります。**実際のLLMアカウント接続とインターネット上のプレイ用サイト公開は、まだ完了していません。** 最新の確認範囲は [docs/STATUS.md](docs/STATUS.md) を参照してください。

## 遊び方

1. 主催者が部屋を作り、招待URLを友達に送ります。
2. 主催者は自由なお題を1行ずつ入力できます。空欄はAIが新しいお題を作ります。
3. LLMが各お題に新しい回答候補を作り、全員が自分のお題に8〜60文字で回答します。
4. 五枚のカードを読んで話し合い、秘密投票します。作者は自分の端末だけで「潜伏役」と分かり、カモフラージュ投票ができます。
5. 正解と作者を公開。正解は100点、作者は誤答した人の割合に応じて最大200点です。
6. 全員が一度ずつ作者になったら結果発表。同じメンバーで再戦できます。

## ローカル起動

Node.js 24を使用します。依存パッケージのインストールは不要です。

```sh
npm run build
npm run validate
npm test
npm run dev
```

`npm run dev` が表示する `http://127.0.0.1:4317` を開きます。ローカル状態は無視対象のSQLiteファイルに保存されます。

デフォルトはライブ生成です。接続がなければ「生成サービスは接続準備中」と表示し、固定回答で代用しません。サーバーの環境変数は [.env.example](.env.example) を参照し、既存の接続や安全なAPIキー設定フローで用意してください。キーはフロントエンドやGitに置かないでください。

生成サービスを使わず画面とルールだけを試す場合は、`GENERATION_MODE=demo` を指定します。このモードだけ24お題・192回答の固定素材を使い、画面にデモと表示します。デモのお題が尽きたら繰り返さず停止します。

## 生成と重複防止

- `worker/llm.js` がサーバーからChat Completions APIを呼びます。標準設定は `gpt-4.1-mini`。`LLM_MODEL` と `LLM_BASE_URL` でOpenAI互換プロバイダーへ変更できます。
- お題とAI回答だけをAPIへ送ります。**プレイヤーが書いた回答は生成APIへ送りません。**
- 同じ部屋の過去のお題・AI回答を生成時の除外候補に含めます。正規化した完全一致と、部屋内の類似表現を検査します。
- D1に保存した生成素材のハッシュで、他の部屋を含めた30日間の完全一致も拒否します。類似判定は部屋内の履歴に限ります。
- 重複や形式違反で有効な候補が不足した場合は、ゲームを始めず再生成へ進めます。永久にあらゆる意味の重複がないと保証する仕組みではありません。
- 生成APIの呼び出しは既定でサイト全体100回/UTC日、1部屋30回までです。HTTPエラーも呼び出し枠を消費します。ゲーム開始後の人間の回答・投票は追加の生成呼び出しを行いません。

API形式は [OpenAI Structured Outputs](https://developers.openai.com/api/docs/guides/structured-outputs)、モデル互換性は [GPT-4.1 mini公式文書](https://developers.openai.com/api/docs/models/gpt-4.1-mini) に基づきます。互換プロバイダーがJSON Schemaに対応しない場合は、`LLM_JSON_MODE=json_object` を設定できます。

## サイト公開

Cloudflare Worker形式の単一ESMとD1マイグレーションを生成します。

```text
dist/server/index.js
dist/.openai/hosting.json
dist/.openai/drizzle/
```

Sitesでは、新しいSiteのIDをローカル `.openai/hosting.json` に登録し、D1の `DB` バインディング、生成APIのサーバー側secret、ライブ設定を用意した上で、対応するソースとビルドを保存・公開します。公開する相手に合わせてSiteのアクセス設定も指定します。

個別SiteのID、APIキー、ローカルDB、参加トークン、端末固有の状態はこのリポジトリに含めません。GitHubへのコード公開と、みんなが遊べるサイトの公開は別の工程です。

## MCP

`POST /mcp` に、`get_game_rules` と `create_party_room` を提供します。初期化・ツール一覧・呼び出しに対応しています。主催者専用リンクには部屋を操作する権限が含まれるので、友達には `invite_url` を共有してください。

Sites上のOAuth・プラグイン接続は、実際の公開後に別途確認します。ローカルのMCPテストだけで接続済みとは扱いません。

## 開発

- `web/` — 日本語の画面、スマホ対応、入力・投票・再接続。
- `worker/engine.js` — 部屋・役割・得点・D1の更新制御。
- `worker/llm.js` — 動的生成・履歴・重複除外・利用回数制限。
- `drizzle/` — 追記するD1マイグレーション。
- `scripts/` — ビルド、検証、ローカルSQLiteプレビュー。
- `data/prompts.json` — 明示的なデモモード専用の素材。

`worker/index.js` と `dist/` は生成物です。修正は元のファイルへ行い、ビルドとテストを実行してください。CIは外部APIキーなしで、ゲームと生成経路をモック通信で検証します。
